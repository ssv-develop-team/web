# WVP-SSV-Web 初始设计规格

## 文档状态

本规格定义独立 Web 前端项目的首期目标和边界。仓库保留了 `reference/wvp-ssv/` 中的旧 Web 源码快照，仅供理解原型行为和接口线索；它不属于本项目实现，也不保证可运行。本阶段不新增可运行的前端代码或构建配置。

## 背景

事件账本和证据文件由 `wvp-ssv` Agent 持有。旧 Web 原型的源码快照已放入 `reference/wvp-ssv/`，作为理解事件列表、详情、结论与图片关联方式的参考；新前端不依赖该快照运行。

随着页面增加多路实时视频，浏览器界面将包含重复的视频格、逐路播放状态和独立的媒体资源生命周期。前端需要独立的源码边界和组件结构。账本与分析服务由 `wvp-ssv` 提供；供页面使用的事件查询 API 和媒体播放接口需在集成阶段确认。

## 目标

- 在同级仓库 `wvp-ssv-web` 中维护 SSV Web 前端源码。
- 采用 Vue 3、TypeScript 和 Vite，按页面功能和播放格拆分组件。
- 保留事件概览、事件列表、事件详情、结论与证据图片关联能力。
- 增加单站点实时视频预览页面，最多显示 3×3 路视频；每格可独立选择、开始、停止和报告播放状态。
- 通过服务端 API 获取事件数据、登记图片和浏览器可播放的媒体源；浏览器不直接连接 RTSP，也不直接访问 SQLite 或 Redis。
- 维持单机或单站点使用，不引入租户模型。

## 用户流程

### 事件查看

1. 用户从概览进入事件列表，可按确认后的 API 契约筛选和分页。
2. 用户打开事件详情，查看检测记录、复核结论和已登记图片证据。
3. 页面依据 `event_id`、`revision` 和 `evidence_id` 关联结论、历史记录及证据；无法匹配的引用应明确显示未登记或不可用。

### 九宫格实时预览

1. 用户打开实时预览页，在最多九个格子中选择可用视频源并发起播放。
2. 每个格子分别呈现空闲、连接中、播放中、重连中或失败状态。
3. 用户可单独停止、替换或重试某一路视频；单路失败不应清除其他格子的播放状态。
4. 页面离开或关闭单格时释放该路播放器和网络资源。

## 架构边界

- **前端项目**：拥有 Vue 页面、组件、状态管理、浏览器播放器适配和 Vite 构建产物。
- **SSV Agent**：拥有 SQLite 账本、证据文件和服务端配置。事件查询、图片读取 API 的实现位置与部署方式需在集成阶段确认；本项目不会直接访问数据库或证据文件。
- **视频接入服务**：负责设备接入、播放会话和媒体转发。前端只消费经过服务端授权、浏览器可解码的播放地址或会话信息。
- **数据与媒体分离**：事件列表、事件证据和实时视频分别通过其明确接口获取；不根据事件时间戳猜测实时画面与历史事件帧的对应关系。

开发时由 Vite 将同源 `/api` 请求转发至已确认的后端 API。部署时前端构建产物与 API 使用同源入口，由 Agent 服务或部署侧 Web 服务器提供静态资源和 API 转发；具体归属与交付方式在集成阶段确定。旧快照中的 Agent Web 服务不视为当前后端能力。

## 播放技术约束

- 浏览器不原生播放 RTSP；播放前必须确认 WVP/ZLMediaKit 当前部署实际提供的浏览器兼容协议和会话控制接口。
- 首先验证单路播放与停止，再验证目标浏览器和目标机器的九路并发解码能力。协议选择依据实测延迟、稳定性、CPU/GPU 使用和部署服务能力，不在前端框架选择中预设。
- 播放器封装必须拥有清晰的创建、错误通知、重连和销毁生命周期。每个视频格隔离自己的播放实例和故障状态。
- 前端构建文件不得包含长期有效的 WVP、ZLMediaKit 或 Agent 控制凭据；如播放流程需要授权信息，由服务端会话接口提供短时播放参数。
- 首期实时格展示原始视频。检测框、事件统计或分析结论需要独立的数据契约和时间对齐依据，不能由播放器组件自行推断。

## 技术选择

- 前端：Vue 3 + TypeScript + Vite。
- 组件边界：事件概览、事件列表、事件详情、视频墙、单路播放器、源选择器和播放状态分别建模。
- 播放器库及媒体协议：通过单路与九路能力验证后再选定；播放器库应被适配层隔离，避免页面组件依赖具体协议实现。
- 后端：由 `wvp-ssv` Agent 或部署侧服务提供经确认的 HTTP API；本仓库不复制账本、证据读取和媒体授权逻辑。
- 通信：前端与事件 API 使用同源 HTTP；实时媒体使用经验证的浏览器播放协议。

## 非本阶段范围

- 多租户、账号体系、角色权限和面向公网的服务开放。
- 事件写入、人工复核、规则配置、模型配置和 Agent 任务控制。
- WVP/NVR 管理、设备注册维护、云台控制和长期录像检索。
- 浏览器直接连接 RTSP、直接访问账本文件或从 Redis 读取事件。
- 实时视频上的检测框、历史事件与实时画面自动同步，以及跨通道事件联动。
- 本设计阶段的可运行前端实现、依赖清单、播放器库和构建配置；`reference/wvp-ssv/` 中的旧快照仅供阅读。

## 验收标准

### 本次文档阶段

1. 在 `wvp-ssv` 同级建立名为 `wvp-ssv-web` 的独立 Git 仓库。
2. 当前项目尚无可运行前端实现或构建配置；旧 HTML、CSS、JavaScript 只存在于明确标注的 `reference/wvp-ssv/` 快照。
3. 文档明确前后端所有权、事件证据关联、九宫格用户流程和播放协议验证关口。
4. 原 Agent 账本和证据职责与前端边界清晰；初始发布提交只包含设计文档、项目入口和明确标注的旧源码参考快照，不包含可运行的前端实现。

### 后续实现阶段

1. 事件页通过集成阶段确认的后端 API 查询；结论和证据按稳定 ID 关联。
2. 单路播放可开始、停止、失败恢复，并在销毁后释放播放器资源。
3. 九路同时播放时，各格状态独立；单格失败不会中断其他视频。
4. 在已记录的目标浏览器、操作系统和硬件上连续运行九路播放并达到后续验收阶段规定的稳定性指标。
5. 前端构建产物能够通过部署选定的同源 Web 入口访问事件 API 和媒体会话接口。
