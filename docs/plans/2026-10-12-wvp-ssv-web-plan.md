# WVP-SSV-Web 初始实施计划

**规格**：`docs/specs/2026-10-12-wvp-ssv-web-spec.md`

**目标**：把浏览器前端源码从 `wvp-ssv` 的 Agent 包中独立出来，并为事件证据查看和九宫格实时视频预览建立可维护的前端项目边界。

**当前阶段**：建立本地设计仓库并迁入旧 Web 源码作为只读参考快照。`reference/wvp-ssv/` 下的 HTML、CSS、JavaScript 和 Python 代码不属于新实现，不保证可以运行；此阶段不新增前端实现、构建配置或依赖清单。

## 步骤 1：建立独立设计仓库

涉及文件：

- `docs/specs/2026-10-12-wvp-ssv-web-spec.md`：定义项目目标、事件页面、九宫格流程、所有权边界和非目标。
- `docs/plans/2026-10-12-wvp-ssv-web-plan.md`：记录当前文档交付范围与后续实施顺序。
- `README.md`：提供项目状态和主要文档入口。
- `reference/wvp-ssv/`：保留旧 Agent Web 服务、静态页面、测试、CLI 上下文和旧 spec/plan，供理解既有行为；不作为新项目运行代码。
- `.git/`：使用 `main` 分支创建初始提交并配置 `origin` 发布；远端已有历史时先检查，不强推覆盖。

验证：确认仓库路径为 `/home/Tiger/Documents/code/web/wvp-ssv-web`；参考源码与来源逐文件一致且文本可读；新实现目录尚无前端代码和构建文件；初始提交推送至远端 `main` 并核对提交 SHA。

## 步骤 2：确认播放接口与九路解码基线

涉及文档：

- `docs/specs/2026-10-12-wvp-ssv-web-spec.md`：根据实际接口能力修订协议和授权边界。
- `docs/plans/2026-10-12-wvp-ssv-web-plan.md`：记录播放验证步骤、目标设备和验收口径。

工作内容：确认事件列表、详情、结论和图片读取的后端 API 契约及责任归属；旧快照里的路由仅作为参考，不能假定仍在运行。核实当前 WVP/ZLMediaKit 提供的播放会话创建、停止及浏览器媒体协议；先验证单路，再测九路并发。记录浏览器、操作系统、硬件解码能力、分辨率、码率、延迟和持续运行表现。验证前不选择播放器库，也不实现九宫格。

验证：能够用明确的服务端接口获取和终止一路播放；确定九路实验使用的播放协议及其运行限制，并形成可复现的测试记录。

## 步骤 3：创建前端工程基础

涉及文件（后续新增）：

- `package.json`、锁文件、`vite.config.ts`、`tsconfig.json`：建立 Vue 3、TypeScript 和 Vite 工程。
- `index.html`、`src/main.ts`、`src/App.vue`：建立入口、根布局和基础路由。
- `src/shared/api/`：封装同源后端 API 请求和错误处理。
- `src/shared/player/`：定义与具体播放协议隔离的单路播放器接口。

工作内容：配置本地 Vite `/api` 代理，建立页面骨架和类型检查；播放器接口先使用测试替身，不接入实际流。

验证：开发服务能启动；API 代理、路由、类型检查和构建通过；产物不包含服务端凭据。

## 步骤 4：迁移事件只读页面

涉及文件（后续新增）：

- `src/features/events/`：实现概览、事件列表、详情、复核记录和证据图片。
- `src/shared/api/`：按步骤 2 确认的后端 API 契约实现类型化调用。
- 后端 API 所属仓库的接口文档与实现：按步骤 2 确认责任归属后纳入集成计划；旧快照路径不代表当前文件存在。

工作内容：以 `reference/wvp-ssv/` 中的旧页面和 API 测试作为行为参考，使用经确认的 `event_id`、`revision`、`evidence_id` 契约关联事件、结论和图片；前端不访问 SQLite、Redis 或本机证据路径。

验证：筛选、分页、事件详情、历史结论、图片查看和缺失证据状态与既有行为一致；页面请求保持同源；事件 API 回归测试通过。

## 步骤 5：验证单路播放器并实现视频格

涉及文件（后续新增）：

- `src/features/live-grid/`：视频墙布局、源选择、单格操作和九路状态。
- `src/features/live-grid/components/`：播放器格和连接状态组件。
- `src/shared/player/`：选定媒体协议的浏览器播放器适配及资源释放。
- `src/shared/api/`：播放会话创建、停止和短时授权参数接口。

工作内容：先集成步骤 2 选定的单路播放协议，验证一个格子的完整生命周期，再扩展至九格。为每格隔离播放器实例、错误和重连，避免一格的销毁或失败影响其他格。

验证：单路开始、停止、切换和故障恢复可用；关闭页面或格子后网络与播放器资源得到释放；九路目标负载的稳定性测试通过。

## 步骤 6：集成部署与端到端验收

涉及文件（根据部署选型后确定）：

- 经步骤 2 确认的后端服务或部署侧 Web 服务器配置：发布前端构建产物并保持同源 API。
- `docs/` 下的部署和操作文档：记录前端构建、产物发布、后端 API 版本约束和运行限制。

工作内容：决定由哪个服务或部署侧 Web 服务器提供构建产物与 API 代理；校验 API 版本兼容、播放会话安全、缓存策略和资源路径。保留前端源码在本仓库单一维护，不在 Agent 源码中手工复制页面源码。

验证：事件及图片 API、播放会话与静态资源经选定入口可访问；在目标浏览器完成事件查看和九路实播验收；重启前后无残留播放器会话。

## 变更顺序约束

- 步骤 1 完成后先由用户审阅设计文档，再开始步骤 2 的外部播放能力验证或后续实现。
- 步骤 2 的播放协议和硬件基线通过实测后，才确定播放器库与九路验收指标。
- 步骤 4 与步骤 5 分开验收，事件证据 API 不承担实时视频转码或播放会话所有权。
- 修改 `wvp-ssv` 时先检查其当前工作区，保留现有未提交内容；只修改集成所需文件。
